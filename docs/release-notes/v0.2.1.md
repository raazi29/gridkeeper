# Gridkeeper v0.2.1 (unreleased)

## Changes

- **Low-memory warnings (Windows, Linux).** Gridkeeper reads the free commit (RAM + page file, including what a
  growable or system-managed page file can still add) every 5 s. Below
  2 GB free (5 % of the limit on large machines) a banner and a status-bar chip show how much is left, the programs
  using the most memory and Gridkeeper's agents' share. Below 1 GB (2.5 %) the level is critical: new launches,
  including restored sessions and formations, wait until memory recovers or *Launch anyway* is pressed (restarts are
  never held). One banner per
  level; it comes back only after memory has recovered. Settings › Interface turns the warnings and the launch hold
  off. Previously the machine could run out of commit with no warning, and Gridkeeper and its WebView2 processes
  then crashed, ending every agent (ADR-024).
- **Emergency reserve (Windows).** Gridkeeper commits 64 MB at startup and releases it when memory becomes critical,
  so its own allocations still succeed while it shows the warning; it takes the reserve back once memory is ok again.
