# Gridkeeper v0.2.0

Covers everything since v0.1.1. Gridkeeper is a Tauri desktop app that runs many AI coding agents in terminal panes.

## Highlights

- **Mission Control.** A shared task board (`.gridkeeper/mission.md`) that agents update themselves, on a zoomable
  canvas with board, timeline and list views, sign-off evidence and a replay video. One session can be the lead,
  under Off, Advisor or Autopilot per project.
- **Brain.** Long-term project memory in `.gridkeeper/brain/`: Markdown notes, suggestions you approve, a generated
  `INDEX.md`, search, optional sharing through git.
- **Exact Claude Code status and a daily spend guard.** Hooks report permission prompts, questions, tool use and
  turn ends; a per-workspace budget can warn or pause Autopilot.
- **Test runs and a merge assistant.** Contained test runs per agent or lane, and a previewed, guarded merge with
  rollback and worktree clean-up: the first git write operation.
- **Browsers.** Native browser panes on Windows (one WebView2 child view per pane), and an agent browser: one shared
  headless Edge or Chrome with a tab per agent.
- **Team templates and phone alerts.** Export and import a team as `.gridkeeper-team.json` or start from the gallery;
  opt-in alerts through ntfy with generic text.
- **12 languages,** including right-to-left Arabic.
- **macOS and Linux builds.** A `.dmg` (Intel; Apple Silicon runs it through Rosetta 2), an AppImage and a
  `.deb`, alongside the Windows installer.

## Changes

Mission Control
- Board: drag cards between lanes, reorder lanes, collapse them, drop an agent on the lead box. Tasks can be
  dragged between states, quick-added, edited in place, assigned and filtered. Keyboard alternatives exist.
- Lead control: in Advisor mode the lead writes instructions to `.gridkeeper/outbox/` and you Send, edit or dismiss
  each one. In Autopilot they are typed in automatically, only into an idle pane that is not asking anything.
  The lead reads `.gridkeeper/team.md`. Optional auto-review asks the lead to review a finished branch.
- Sign-off evidence: commits ahead, files and lines changed, uncommitted leftovers, plus a Review diff button.
  The Changes drawer now shows a branch's committed work (`base...HEAD`), not only `git status`.
- Replay: missions are recorded as events only (no terminal output, paths or e-mails) and rendered in the app to
  MP4, WebM or GIF, 15 to 60 s, three aspect ratios.
- Flight log: local streak, ranks and medals from completed mission tasks.
- Cost and context meter for Claude Code panes (opt-in), read from the documented status-line data.
- Skills panel: find Agent Skills on GitHub, review them and add them to the project.
- Canvas: zoom (Ctrl+wheel or pinch, 25 to 200 %) and pan, fit, a minimap (Shift+M, off by default); the view is
  kept per workspace.
- Views: graph, board (tasks per agent or per lane, drag to reassign), timeline (each agent's state over time with
  task and message markers) and a sortable list; keys 1 to 4.
- Find (Ctrl+F) over agents and tasks, role and state filters, spotlight, pins, multi-selection with bulk message /
  restart / stop / move / assign through the existing confirmations, and a resizable agent side panel (state,
  tasks, branch evidence, usage, CPU / RAM, last output lines).
- Motion: message animations along card-to-card links, gliding cards and lanes, a gold effects layer and a
  briefing crawl. Effects have a setting and honor reduced motion.
- Layout: sign-off box in the flow, board and lead side by side, foldable river and log, no clipped text.

Brain
- Notes in `.gridkeeper/brain/notes/` (decision, convention, gotcha, how-to, fact, context), suggestions in `inbox/`
  and an `INDEX.md` regenerated from the notes. Writes are atomic, redacted, capped at 16 KiB and conflict-checked.
- Suggestions are captured from the mission board (`- note:` lines on finished tasks, approved reviews, resolved
  blockers, new `fix:` tasks) and from lead decisions; auto-approve is a per-project option for these only.
- Brain panel: local search (BM25-style ranking), kind and tag filters, approve, edit, supersede, forget with Undo,
  and a "remember" chip for text selected in Mission Control.
- Briefs and formation starter prompts point agents at `INDEX.md` and `inbox/`. Sharing through git adds a marked
  `.gitignore` block for `notes/` and `INDEX.md`; the inbox stays local. The format is in the `agent-mission` skill.

Claude Code status and spend
- Exact status from hooks (on by default while the cost meter is on): the meter's per-pane `--settings` file adds
  Claude Code hooks, which Claude Code merges with the user's own; those are neither read nor changed. Gridkeeper
  keeps only the event, tool name, notification type and session id.
- Hook states take precedence over output heuristics. Pane headers and Mission Control cards show messages such as
  "Needs permission · Bash". Autopilot and hand-offs refuse while a permission or question prompt is open.
- Spend guard: a daily budget per workspace from the cost meter's numbers, a warning toast at a chosen share, and at
  100 % warn only, pause Autopilot, or pause and notify. A banner offers Raise budget and Resume. Agents are never
  stopped. Today's spend shows in Mission Control and in Fleet.

Test runs and merge assistant
- Test runs: the command is detected (`package.json` by lockfile, `Cargo.toml`, pytest config, `go.mod`, a Makefile
  `test` target) or set per workspace and per lane. Runs happen in the session's worktree in their own process
  container, below normal priority, with a time limit (default 15 min), a queue (default 2 at once), a 2 MiB output
  ring and git HEAD recorded at start and end. Best-effort summaries for vitest, jest, cargo, pytest, go and mocha.
- Badges on agent and sign-off cards, a read-only log viewer, and "ask the agent to fix", which is never sent
  without confirmation.
- Merge assistant (ADR-022): preview with `git merge-tree` (a temporary worktree on git older than 2.38);
  fast-forward, merge commit or squash of the previewed commit in the main checkout. Refused when the main checkout
  has another branch, tracked changes, an operation in progress or `index.lock`, or when a branch moved since the
  preview. Optional test gate. Failed steps are rolled back and checked. Worktree and branch clean-up is a separate
  confirmation and unlinks junctions before `git worktree remove`.

Browser
- Native browser panes on Windows (ADR-021): one Tauri child webview per pane, with in-page history, real titles,
  new-window links in a new or the same pane, downloads to the Downloads folder and app shortcuts that work from
  inside a page. A covered pane shows a snapshot. Settings > Interface > Browser engine switches to the iframe
  engine (Embedded frame (legacy)), which macOS and Linux keep using.
- Agent browser: opt in per Claude Code or Codex session. One headless Edge or Chrome per Gridkeeper instance with
  its own profile, driven over a pipe (no debugging port), a tab per agent, closed after idle minutes. Tools are
  served by the MCP helper `gridkeeper --gk-mcp-browser`, added per process (`--mcp-config` / `-c mcp_servers…`);
  user MCP config is untouched. The Agent browser view shows every tab live, with take over and stop. Form
  submission and scripts outside localhost and the allowlist, uploads and downloads wait for confirmation.

Languages
- 12 locales: English, Spanish, Portuguese (Brazil), French, German, Japanese, Simplified Chinese, Korean, Hindi,
  Russian, Arabic (right to left) and Turkish. Settings > Interface > Language, or the system language. The
  translations are machine-assisted; agent-facing text (briefs, hand-offs, team.md, prompts) stays English.
  See docs/translating.md.

Other
- Team templates: import drops account ids, args, env, absolute paths and recognized secret formats, and accepts
  only built-in agents and catalog presets.
- Phone alerts: one HTTPS POST per alert, one alert per pane per 2 minutes, at most 10 per hour, no retries.
  They respect Do not disturb, mutes, phone quiet hours and minimum priority. The access token is write-only
  in the UI and stored in the OS credential store (Windows) or a 0600 file.
- Closing a pane removes it at once and stops the process in the background. A graceful stop sends a second
  Ctrl+C after 300 ms, so Claude Code and Codex no longer wait out the 2 s grace period.
- macOS: native app menu (App, Edit, View, Window, Help), Cmd+W hides the window and leaves agents running,
  Dock badge for unread alerts.
- macOS and Linux: PATH is read once from the login shell on GUI launches, and common tool folders are added.
  The login shell is the default terminal. Windows-only parts are gated off.
- `gridkeeper --gk-self-test` checks the data folder, the default shell in a PTY, process cleanup and the PATH
  lookup, then exits 0 or 1. CI runs it on all three OSes. `--gk-self-test-gui` starts the real app briefly.
- Package manifests: Scoop bucket, Homebrew cask and winget, refreshed per release by
  `scripts/release/update-manifests.mjs`.
- `agent-mission` and `mission-recap` Agent Skills, installable for other agents.

## Fixes

- A crashed WebView2 renderer or browser process no longer leaves a black window; the page reloads or the
  window is rebuilt, and running agents are kept.
- Session restore no longer relaunches panes the host already knows after a renderer reload.
- Editing a queued lead instruction returns it to "proposal", so Autopilot cannot send half-edited text.
- A late "done" no longer overwrites the "waiting" attention state; panes behind Mission Control count as off screen.
- Window focus inside a browser-pane iframe no longer counts as unfocused.
- A save counts as done only after the write succeeds.
- Closing the main window on Windows and Linux no longer leaves a headless process behind a browser pop-out.
- Mission watch and unwatch are serialized, Escape handling in menus and Comms is fixed, and Mission Control
  card tails keep polling so the final line shows after an agent exits.
- Bare IPv4 hosts and hosts with a port are normalized to `http://`; the browser-pane loading bar no longer sticks.
- Dropdowns and dialogs use one z-index scale.

## Install

Download from https://github.com/raazi29/gridkeeper/releases/tag/v0.2.0.

- **Windows:** NSIS `.exe` (per user). Not code-signed, so SmartScreen may show "Windows protected your PC":
  More info, then Run anyway.
- **macOS 11+:** `.dmg` built for Intel; Apple Silicon Macs run it through Rosetta 2 (macOS offers to install
  it on first launch). Ad-hoc signed, not notarized. On macOS 15 open it once, then System Settings > Privacy &
  Security > Open Anyway. On macOS 14 and earlier, right-click the app and choose Open. On any version:
  `xattr -dr com.apple.quarantine /Applications/Gridkeeper.app`.
- **Linux (x86_64):** `.deb` (recommended) or AppImage. Needs WebKitGTK 4.1; the AppImage on Ubuntu 24.04
  needs `libfuse2t64`.
- Package managers: Scoop, Homebrew cask and winget manifests are in the repo (`bucket/`, `Casks/`, `packaging/winget/`).

## Known limitations

- macOS and Linux are previews: CI builds them, runs the tests and starts the app, but they have had little
  hands-on use. GPU telemetry is Windows only.
- On macOS and Linux, if Gridkeeper is killed hard (SIGKILL, crash, power loss) its agents can keep running.
  Quitting normally stops them. Cmd+Q does not ask for confirmation.
- macOS notifications for the ad-hoc signed build are unverified on macOS 14 and 15.
- The macOS build is Intel-only for now: the CI machine can't build a universal binary within its time limit.
  A native Apple Silicon build is planned.
- No auto-update.
